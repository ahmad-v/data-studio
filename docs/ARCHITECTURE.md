# Architecture

Data Studio: Local tabular data workbench.

Localwright core contains serde-based domain contracts, request/response, capability and engine descriptors, job cancellation, bounded reads, no-clobber output and settings. It has no Iced dependency. Localwright UI is an optional dependency of the studios and provides a generic native operation workbench. It dispatches a single job to a background thread and receives the structured outcome through a channel. The same handler runs through the CLI. Studio processing lives in its own crate. No local server, system engine lookup or runtime network client is intentionally implemented.

Source contracts version 0.1.0-alpha.1; pre-1.0 API is unstable. Use exact shared revision after import. New breaking changes require migration notes and all four consumer checks. The application uses Rust 1.95.0 for its bundled SQLite dependency. No promise of ABI stability. Current settings schema 1. Request and outcome are internal alpha interchange, not stable project file formats.

`inspect-schema` builds a bounded typed columnar view directly from CSV/TSV records and XLSX worksheet cells, or from the existing flat scalar Parquet decoder. XLSX retains native booleans, numbers and date/time values; blank cells become nulls, explicit empty text remains text, and schema overrides are validated during conversion. XLSX archive and worksheet bounds are checked before the typed columns are allocated. `export-typed-parquet` converts that validated view to Arrow scalar types, nulls, dictionary-encoded categories and Arrow field metadata, with nanosecond date/time types. Filter, sort, select-columns and rename-column now perform their processing on typed values for supported CSV/TSV and flat scalar Parquet inputs, including when the resulting table is serialized to CSV or TSV. Delimited output cannot preserve the distinction between a null and an empty string; typed Parquet does. Most other standalone transformations and statistical input routes still use the legacy string table. Nested and binary Parquet columns remain out of scope.

Limitations: Existing processing is still primarily an in-memory text table. There is no large-data virtualization, typed editing or desktop pipeline editor. Typed project schema selection is opt-in and version 1 project files remain backward compatible. There is no general formula language, full worksheet selection, broad format coverage, authoritative palettes or full scientific export. XLSX ZIP expansion and range allocation occur in the dependency before the cell limit; hostile workbooks are not safe for production. CSV formula mitigation modifies formula-like text and cannot prove spreadsheet safety.
